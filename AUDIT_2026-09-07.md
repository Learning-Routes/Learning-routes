# Learning Routes — Audit of the last week's changes (WP-16 → WP-24 §2)

**Date:** 2026-09-07 · **HEAD:** `0b72e98` (main) · **Range audited:** `c4a2ef5..0b72e98` (2026-08-31 → 2026-09-05), 258 files.
**Method:** read-only on a `git archive` of HEAD. Three parallel passes (gating & exam flow; money & spend; front end & rendering), then every finding below was re-verified by opening the file that decides the behaviour. Verdict **CONFIRMED** means the deciding lines are quoted here; **PLAUSIBLE** means the code path is real but the trigger depends on something outside the repo (a model's output, a browser's CSP behaviour).

The week shipped a lot that is right — the answer normalizer, the three-way advancement policy, claim-first enqueues, immutable quotes with DB triggers, webhook replay guards, the parser terminator. What follows is what is still wrong, ordered by what it costs a student or the owner today.

---

## 1. Executive summary

1. **WP-29's gate has a side door.** The layout renders "Completar paso" on every page that has an uncompleted `@step` — including the exam and results pages — and `steps#complete` only gates on blocks and the step quiz, neither of which an assessment step has. A student who scored 0% clicks the header button and the step completes with no `advanced_without_passing` recorded. Separately, after one failed attempt the step page hides the only Start button, so the RELEASE_AFTER escape valve is unreachable from the UI. (§2.1, §2.2)
2. **Do not run `wp24:reparse_scenarios` in production yet.** It rewrites the whole `parsed_sections` array from a fresh parse, and the fresh parse always emits `image_url: nil` — the URLs `MediaPrefetchJob`/`SectionImageJob` wrote into that array are lost, and every illustrated step goes back to "generate image" (paid once the 7-day cache expires). The census is read-only and safe. (§2.5)
3. **Three paid calls run outside `SpendGuard`**, and two controllers spend under the read gate instead of the generation gate: `LessonAssistantAgent` (`RubyLLM.chat` direct), `VoiceEvaluator` (ElevenLabs STT via `Net::HTTP`), and `AssessmentGenerationJob` is enqueued on every 3-second poll with no claim. A refunded route — once refunds exist — keeps spending through the lesson AI buttons, hints and exercise grading. (§3)
4. **A paying customer cannot get content.** `ContentPipelineJob` refuses any step whose module is not `preview` and releases the claim; the step page re-claims and re-enqueues on the next poll. One job every 3 s per paid student, forever, and a skeleton on screen. Task 8 is the real fix; a two-line stopgap belongs before it. (§3.4)
5. **The "client swallows the server's verdict" class has more instances than the six the tablero counts:** `completeLesson` celebrates on any non-422 failure; `submitBlock` returns `null` on every refusal and the gate shows only "Answer to continue"; the wrong-deletion-code error renders into a hidden element; the voice recorder's "Record again" button has no label because its start tag is never closed. (§4)
6. **The parser still drops trailing content after `## Pregunta` and `## Match`** — and the lesson prompt places one of its two required mermaid diagrams right after `## Pregunta`. The same double-escape WP-24 §2 removed from scenarios is live in the playground's Reset. (§2.6, §4.3)
7. **Repo hygiene:** `_to_delete/` (git lock files, an `exam.html.erb`, an audit doc) is committed and ships in the Docker image; `db/schema.rb` is a stale fossil next to the authoritative `structure.sql`.

## 2. Gates, exam flow, persisted sections

### 2.1 [P0] The header "Completar paso" button completes an assessment step without passing — CONFIRMED

`app/views/layouts/learning.html.erb:83-89`
```erb

```
`AssessmentsController` and `ResultsController` both use `layout "learning"` (`:3`) and set `@step = @assessment.route_step` (`assessments_controller.rb:12,52`, `results_controller.rb:11`), so the button is on the exam page and on the results page.

`steps_controller.rb:27-73` (`complete`) gates on `@step.outstanding_blocks_for(current_user)` — empty for an assessment step because `SectionResolver#lesson_content` finds no `AiContent` (`section_resolver.rb:63-67`) — and on `@step.requires_quiz?`, which is `content_type_lesson? || content_type_exercise?` (`route_step.rb:110-112`), false for assessments. ### 2.2 [P0] After one failed attempt there is no way to retake — CONFIRMED

`steps_controller.rb:343-345`
```ruby
@existing_result = Assessments::AssessmentResult.find_by(user: current_user, assessment: @assessment) if @assessment
```
No `score` filter, no order — an arbitrary row. `steps/_assessment.html.erb:17-76`: `<% if @existing_result&.score.present? %>` renders the score ring and "Ver resultados"; the only `start_assessment_path` button is in the `else` branch (`:72`). `results/show.html.erb:67-72` links only back to the route or to the next step. (This also explains why the 4 September live test *could* start: `find_by` returned an open attempt that day.)
Fix: select `.where(score: nil)` first, else `.order(:created_at).last`; show the Start button whenever `!@step.completed?`, labelled "retake" when a scored result exists.

### 2.7 [P2] Two races in the same class — CONFIRMED (code), race needed

*Corrected 7 September after WP-32 ran both paths: the second item was a 422 with no message, not a 500 — Rails maps `RecordInvalid` to `:unprocessable_entity` — and Rails 7.1's `find_or_create_by` already retries on `RecordNotUnique`. Fix: `create_or_find_by!` + `rescue RecordInvalid` → `find_by!`.

## 3. Money and spend

### 3.1 [P1] `LessonAssistantAgent` bypasses `SpendGuard`; lessons and exercises spend under the read gate — CONFIRMED

`lesson_assistant_agent.rb:58` `chat = RubyLLM.chat(model: "gpt-4.1-mini")` — not through `AiClient`, so no `SpendGuard.call` (`ai_client.rb:22` claims "EVERY paid provider call goes through here"). `lessons_controller.rb:35` and `exercises_controller.rb:93` use `authorize_route_step_access!`, while every other paid endpoint uses `authorize_route_step_generation!` (`section_images_controller.rb:9`, `section_audio_controller.rb:9`, `audio_controller.rb:7`). The ceiling can be at 100 % and each student still fires ten gpt-4.1-mini calls per hour per step from the AI buttons, and `quick_grading`/`exercise_hint` on a refunded route.
Tests miss it because the sweep at `spend_guard_test.rb:68` selects files containing `AiClient.new`.
Fix: `SpendGuard.call` at the top of `LessonAssistantAgent#interact`; switch both controllers to the generation gate; extend the sweep to `RubyLLM\s*\.\s*chat` and provider hostnames outside `ai_client.rb`.

### 3.2 [P2] `VoiceEvaluator` transcribes outside every ceiling — CONFIRMED

`voice_evaluator.rb:46-62`: `URI("https://api.elevenlabs.io/v1/speech-to-text")` … `http.request(request)`, no `SpendGuard`. Cost is metered after the fact (`speech_paths_metering_test.rb`) but never gated; `rate_limit to: 10, within: 5.minutes` is the only brake. Fix: `SpendGuard.call(model: STT_MODEL, task_type: :transcription, user:)` before the request.

### 3.3 [P1] Refund webhooks are consumed as `unsupported_event`, so `mark_refunded!` can never be reached — CONFIRMED

`order_processor.rb:21` `SUPPORTED_EVENTS = %w[order_created]`; `:50-54` claims the identity **before** `return "unsupported_event"`. `route_purchase.rb:55-59` `mark_refunded!` has no caller outside `test/`. When Task 9 ships, a dashboard resend of the same `order_refunded` event is answered `duplicate_event` because the identity is already taken. Task 9 must therefore either re-claim `rejected` identities or stop claiming identities for unsupported names — the exact trap `WP18_RESUME.md:131` warns about. Related: `provider_event.rb:83-88` makes any rejection terminal, so a real paid order rejected for `store_mismatch` during misconfiguration can never be re-delivered without DB surgery.

### 3.4 [P1] A purchased module can never generate content and polls forever — CONFIRMED

`content_pipeline_job.rb:24-27`: `unless @step.preview_access?` → `ContentPrefetcher.release` → return, writing no error. `route_step.rb:163-165`: `preview_access?` is `access_state: :preview` only; `OrderProcessor#apply!` flips modules to `purchased`. `steps_controller.rb:255-264` claims with **all** access states and enqueues; `_step_content_frame.html.erb:6-9` polls every 3 s while generating. Purchased step → claim → job releases → poll → claim → … one job per 3 s per paying student, skeleton on screen. Task 8 is the fix; until then the job (or `request_content_generation!`) must mark non-preview steps `content_unavailable`/`not_yet_available` so the poll stops.

### 3.5 [P3] Smaller money findings — CONFIRMED unless noted

- Checkout carries no `expires_at` and the webhook never checks `quote.expires_at` (`providers/lemon_squeezy.rb:42-64`, `order_processor.rb:160-215`): a stale checkout URL pays a retired price weeks later. Pass `expires_at` to the provider.
- `SpendGuard` ceilings sum only `pricing_status: "priced"` rows (`spend_guard.rb:95-97`, `ai_interaction.rb:26`); if ElevenLabs stops sending `character-cost`, TTS is recorded at 0 and the ceiling never trips. Add a conservative estimate for unpriced completed rows.
- `PricingConstants` are pinned again in DB CHECK constraints (`20260901000006_create_commerce_route_quotes.rb:62-64`): changing `MARKUP_BASIS_POINTS` makes every quote `pricing_unavailable`. Drop the literal CHECKs or document the required migration.
- PLAUSIBLE: the full webhook body (`user_name`, receipt URLs) is logged at INFO via Rails' `Parameters:` line — `filter_parameter_logging.rb:6-9` filters none of those keys.
- PLAUSIBLE: `checkouts_controller.rb:24` redirects cross-origin while CSP `form_action` is `:self, accounts.google.com` (`content_security_policy.rb:58`) — a plain form POST to the checkout will be refused by Chrome when the buy button ships.

What is right here and should stay: integer/Rational money end to end; HMAC over `raw_post` with `secure_compare`; claim-first `ProviderEvent` with index-specific `RecordNotUnique`; DB triggers as the final authority on ownership and amount; owner-only, paginated, bound-parameter admin queries; `ContentPrefetcher.claim/release` as the one enqueue path.

## 4. Front end and rendering

### 4.1 [P1] `completeLesson` celebrates on every failure that is not a 422 — CONFIRMED

`interactive_lesson_controller.js:1047-1077`: `response.ok` → data; `422` → the two refusals WP-22 added; **`else` → `console.warn` only; `catch` → `console.error` only**; then `this._showCelebrationScreen(serverData)` runs regardless, with `_completed = true` already set at `:1007`. ### 4.2 [P1] `submitBlock` swallows every refusal; the gate then says only "Answer to continue" — CONFIRMED

### 4.6 [P1] Hardcoded Spanish and English shown regardless of locale — CONFIRMED (class)

### 4.7 [P2] `MarkdownRenderer` lets AI-generated markup carry `data-controller`, `data-action`, `id`, `style`, `<button>`, `<input>` — CONFIRMED (weakness; no privilege gain shown)

`markdown_renderer.rb:93-105`: Redcarpet is built without `filter_html`/`escape_html`, and the sanitizer allow-list includes `button input label` and `id style data-controller data-action`. `<script>`, `on*=` and `javascript:` are stripped — classic XSS is closed — but a hallucinated or injected lesson body can plant `<div data-controller="content-poll">` (polls forever) or `<button data-action="click->interactive-lesson#completeLesson">` inside the `interactive-lesson` scope. ### 4.8 [P2] A correctly answered check is reset when the student navigates back and forward — CONFIRMED
