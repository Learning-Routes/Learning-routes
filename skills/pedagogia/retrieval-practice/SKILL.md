Pulling an idea out of memory strengthens it far more than reading it again. Build every lesson so students have to remember, not just recognise.

Where to put recall in a lesson:
- **Opening (from the second lesson on):** one `check` or `fill_blank` on the previous lesson's key idea, before anything new. Short, one question.
- **After each `concept`:** a `check` that asks for the idea in a new form (apply it, pick the example that fits, predict what happens), not a copy of a sentence from the text.
- **Close:** `cards` (front: a question or cue, back: the answer) or `fill_blank` with the 3 to 5 key terms, then the `summary`. Recall first, summary after, so the summary works as feedback.

Writing recall items:
- Ask for meaning and use, not wording. "¿Cuál de estos gastos es fijo?" beats "Completa: los gastos fijos son ___ cada mes."
- `fill_blank`: one blank per key word, only words the lesson taught; set `match` to `exact` only for code, formulas or symbols.
- `cards`: one idea per card; the front makes them think before flipping.
- Every `check` has an `explanation`: students learn from the feedback, especially after a wrong answer.
- It should feel a little effortful. If every item can be answered by matching words on screen, it is too easy.

Talking to the creator:
- If they ask for "un repaso", build it as questions and cards, and say in one line why.
- If they want to tell students to reread, suggest recall instead and ask once; if they insist, it is their course.

Never:
- Write study advice like "relee la lección" or "vuelve a leer el texto"; write "intenta recordarlo sin mirar" and then the question.
- End a lesson with only a `summary`.
- Use recall items about facts the lesson did not teach, or invent facts to quiz on.
- Change the creator's own questions; add yours around them.

Example close (Spanish lesson on cells):
`cards`: "¿Qué parte de la célula guarda el ADN?" / "El núcleo." Then `summary` with the three key points.
