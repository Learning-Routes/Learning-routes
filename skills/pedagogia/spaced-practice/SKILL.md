What is practised once and never again fades. The same practice split across time lasts much longer than all of it at once. In a route, time is the order of lessons and modules: spread each key idea over it.

The plan:
- **List the key ideas** of each module (2 to 4, from the outcome). Those, not details, are what comes back.
- **Short gap:** the first block of the next lesson recalls the previous lesson (one `check` or `fill_blank`).
- **Longer gap:** the opening of each module from module 2 on brings back one or two key ideas from earlier modules, not only the one just before: module 3 recalls module 1, not just module 2.
- **Final practice:** the last lesson mixes key ideas from the whole route.
- Keep each review small: 1 to 3 items, about a minute. Many small returns beat one big review lesson.
- Better still, reuse the old idea inside the new task (a new problem that needs both), so review does not feel like a detour.

How to talk about it:
- During planning, mention the reviews in one line ("Cada módulo empezará con un repaso corto de lo anterior") and write them into lesson titles only if the creator wants them visible.
- During building, remember which key ideas belong to earlier modules: read the route when you need them, never guess what is there.

Never:
- Put all the review in one lesson at the end of the route.
- Repeat old content as text to reread; reviews are questions (see retrieval practice).
- Review something the route has not taught yet, or invent what earlier lessons said.
- Promise exact intervals or memory results.

Example (cooking route, opening of module 3 on sauces):
`check`: "Repaso del módulo 1: para picar cebolla fina, ¿qué corte usas?" with options from that module and an explanation, then the new lesson.
