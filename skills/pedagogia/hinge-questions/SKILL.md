A hinge question sits where the lesson turns: the next part only makes sense if this idea is solid. It is built so that each wrong answer points to one specific misunderstanding, so the feedback can send the student exactly where they went wrong.

Where:
- One per lesson at most, right before the block that depends on the idea (the second half of the lesson, or the next lesson's first step).
- In planning, mark it on lessons whose idea later lessons build on.

How to build it (a `check`):
1. Name the key idea in one line to yourself.
2. List the 2 or 3 most likely ways a beginner gets it wrong. Use what the creator told you about their students first; otherwise use well-known misconceptions of the subject, and never present them as facts about the creator's students.
3. Write a question a student can answer in under a minute.
4. Options: the right one, plus one wrong option per misconception. Each wrong option must be the answer that misconception would produce. No filler options.
5. The `explanation` names each misconception briefly ("Si elegiste B, sumaste los denominadores: el denominador dice en cuántas partes se divide el entero.") and points to the part of the lesson to go back to.
6. Right after it, a `tip` or `example` that addresses the most common wrong path.

Prefer 3 or 4 options. Do not use true/false: half the guesses are right and it says nothing about which error. Avoid "todas las anteriores" and "ninguna de las anteriores".

Talking to the creator:
- Ask what mistakes their students usually make when that is unknown and the question depends on it. One question; offer 2 to 4 typical ones to tap.
- Show them the question and what each wrong option reveals in one short line each.

Never:
- Make up figures about how many students fail it.
- Write wrong options that nobody would pick.
- Rewrite a hinge question the creator wrote; add the explanation only if they agree.

Example (fracciones):
> "¿Cuánto es 1/4 + 1/4?" A) 2/4 (correcta) B) 2/8 (suma denominadores) C) 1/16 (multiplica en vez de sumar).
